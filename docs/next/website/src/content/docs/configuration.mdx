Herdr works without a config file. Add one when you want custom keys, themes, sidebar layouts, notifications, or advanced behavior.

Looking for any setting or keybinding? Search the [Config reference](/docs/config-reference/) for every key, type, default, and allowed value. This page focuses on setup, common recipes, and configuration structures that need more explanation than a reference row.

## Config file

Herdr reads config from:

```text
Linux and macOS: ~/.config/herdr/config.toml
Windows:          %APPDATA%\herdr\config.toml
```

Run `herdr --help` to see the resolved config path for your system.

Print the full default config:

```bash
herdr --default-config
```

Save it as your config if you want a complete starting point:

```bash
herdr --default-config > ~/.config/herdr/config.toml
```

If a config value is invalid, Herdr falls back to a safe default and shows a startup warning.

## Validate config

Check the config file the same way Herdr loads it, without starting a session:

```bash
herdr config check      # herdr config validate is the same command
```

It prints the resolved config path, then every diagnostic Herdr would report — unknown keys, unknown sections, invalid values, and fallbacks taken — with the line and column each one came from:

```text
config: /home/you/.config/herdr/config.toml
config: issues found
unknown config key theme.custom.accentt; ignoring key (config.toml:8:1)
ui.sidebar_min_width (90) is greater than sidebar_max_width (40) (config.toml:12:1)
```

The exit code is `0` when the config is clean and `1` when there are diagnostics, so it drops into a shell profile check or CI step. Add `--json` for a machine-readable report with `path`, `ok`, and a `diagnostics` array of `{message, line, column}`:

```bash
herdr config check --json
```

A diagnostic whose key path is no longer present in the file — a parse error, or an unreadable file — is reported without a location. With no config file at all, it says so and exits `0`, because running on defaults is a valid state.

Herdr shows first-run setup when `onboarding` is missing or true. Continuing from onboarding writes `onboarding = false` and opens settings on the integrations tab. Set it when you want to skip that flow after setup.

```toml
onboarding = false
```

## Reload config

Reload a running server after editing `config.toml`:

```bash
herdr server reload-config
```

You can also open the global menu in Herdr and choose `reload config`.

Reload applies most UI settings without restarting panes. Startup-only settings still need a restart.

## Terminal defaults

Set the executable Herdr uses for newly created interactive panes:

```toml
[terminal]
default_shell = "nu"
```

When unset or empty, Herdr uses `$SHELL`, then `/bin/sh` on Unix and PowerShell on Windows. This is an executable name or path, not a shell command line. Existing panes keep their current shell until they are recreated. Custom command keybinding strings run through `/bin/sh -c` for pane commands and `/bin/sh -lc` for detached commands on Unix; on Windows they run through `cmd.exe /d /c`.

Set how Herdr starts newly created interactive pane shells:

```toml
[terminal]
shell_mode = "auto"
```

`shell_mode = "auto"` starts login shells on macOS so login-only PATH setup such as `/usr/libexec/path_helper` and Homebrew shell initialization runs in new panes. On other platforms, it keeps the existing non-login shell behavior. Use `"login"` to force login-shell startup, or `"non_login"` to opt out. Command panes, detached custom command keybindings, and explicit argv launches keep their existing command execution paths.

Set the working directory policy for new panes, tabs, and workspaces:

```toml
[terminal]
new_cwd = "follow"
```

`new_cwd = "follow"` keeps the default behavior and inherits the source pane or workspace. When there is no source workspace, Herdr starts in `$HOME`. Use `"home"` to always start in `$HOME`, `"current"` to use Herdr's process directory, or a fixed path such as `"~/Projects"`. Explicit `--cwd` values from the CLI or socket API still take precedence.

## Worktrees

Set the root directory Herdr uses for Git worktree checkouts created from the sidebar:

```toml
[worktrees]
directory = "~/.herdr/worktrees"
```

Herdr creates checkouts under `<directory>/<repo>/<branch-slug>`. For sibling-style checkouts, set this to a directory such as `~/Projects/herdr-worktrees`. Relative values are resolved to an absolute path when the app applies the config.

Worktree actions are available from Git workspace rows. `New worktree` creates a checkout, checks out an existing local branch when the entered branch already exists, otherwise creates the branch, opens it as a new Herdr workspace, and groups it under the source workspace. `Open worktree...` lists existing Git worktree checkouts for that repo; choosing an already-open checkout focuses it, and choosing a closed checkout opens it in the same group.

Grouped worktrees still behave like normal Herdr workspaces: they can be focused, renamed, closed, and contain their own tabs and panes. The parent row is the original workspace. Closing the parent row closes the whole Herdr group, but it does not delete checkout folders or branches.

A Space group always means the same thing: the parent row is the repo's main checkout and every indented row is a linked Git worktree of it. Only linked worktrees are ever indented, and a group only appears once the repo has at least one linked worktree open. So if you open a second workspace in the same main checkout, it keeps its own top-level row instead of appearing as a worktree of the first one, and closing it closes only that workspace. When several workspaces share one main checkout, the first of them in sidebar order is the group's parent row.

Deleting a worktree checkout is explicit. Use `Delete worktree checkout...` on a grouped child workspace to run `git worktree remove`. Herdr first asks Git to remove safely. If Git refuses because the checkout has modified or untracked files, Herdr asks again before running the forced remove. Branches are not deleted.

## Remote attach

Remote attach manages its SSH connection with a temporary keepalive and connection-reuse fallback by default.

```toml
[remote]
manage_ssh_config = true
```

When enabled, `herdr --remote` writes a private temporary SSH config that includes your `~/.ssh/config` and `/etc/ssh/ssh_config` first, then adds fallback `ServerAliveInterval` and `ServerAliveCountMax` values. Your own keepalive settings win. Herdr also uses a private per-attach OpenSSH control socket to reuse the first authenticated connection. Set `manage_ssh_config = false` to run remote attach through plain `ssh` without Herdr's generated config or control socket.

## Keybindings

For a guided introduction to the prefix and a vetted prefix-free setup, see [Keyboard](/docs/keyboard/).

Herdr has a prefix mode similar to tmux. The default prefix is `ctrl+b`. Keybinding strings are explicit: `prefix+n` means press the configured prefix and then `n`; `ctrl+alt+n` is a direct terminal-mode shortcut.

A small keybinding override looks like this:

```toml
[keys]
prefix = "ctrl+b"
goto = "prefix+g"
new_tab = "prefix+c"
next_tab = "prefix+n"
previous_tab = "prefix+p"
focus_pane_left = "prefix+h"
navigate_workspace_down = "j"
navigate_pane_down = "ctrl+j"
split_horizontal = "prefix+minus"
```

The default keymap is prefix-first so Herdr does not steal input from shells, editors, tmux, or terminal apps. Search `keys.` in the [Config reference](/docs/config-reference/) to see every action and default binding. The in-app help panel at `prefix+?` shows the active bindings.

A binding may also be an array when one action needs multiple shortcuts:

```toml
[keys]
next_tab = ["prefix+n", "ctrl+alt+]"]
```

Optional actions are unset by default. Bind them with `prefix+` for prefix-mode behavior, or use an explicit modified chord when you intentionally want a direct shortcut.

Key strings accept plain keys, modifier combinations such as `ctrl+a`, `shift+n`, `alt+1`, `cmd+k`, and special keys such as `enter`, `tab`, `esc`, `left`, `right`, `up`, and `down`. Named punctuation such as `minus`, `comma`, `ampersand`, `plus`, and `backtick` is also accepted. Plain direct printable keys such as `n` are unsafe because they intercept typing; use `prefix+n` unless you intentionally want a direct binding. The `navigate_workspace_*` and `navigate_pane_*` fields are navigate-mode-only and may use plain keys such as `j` or `k`; they must not use `prefix+`, `esc`, `enter`, `tab`, `shift+tab`, `left`, `right`, or unmodified `1` through `9`. Left and right arrows are permanent aliases for pane-left and pane-right navigation. These navigate-mode shortcuts are independent from general action bindings such as `focus_pane_down = "prefix+j"`; when both use the same key, the navigate-mode shortcut wins while navigate mode is open. Alt, Cmd/Super, and punctuation with modifiers depend on your terminal and tmux settings.

If you have old custom keybindings and want the new defaults, run `herdr config reset-keys`. Herdr backs up `config.toml`, removes `[keys]` and `[[keys.command]]`, and uses built-in v2 defaults after restart or `herdr server reload-config`.

## Indexed jumps

Indexed keybindings use `1..9` in normal keybinding fields:

```toml
[keys]
switch_tab = "prefix+1..9"
switch_workspace = "prefix+shift+1..9"
focus_agent = "prefix+alt+1..9"
```

The legacy `[keys.indexed]` table is still parsed for compatibility, but new configs should prefer the explicit action fields.

## Custom command keybindings

Custom commands use the same keybinding syntax.

```toml
[[keys.command]]
key = "prefix+alt+g"
type = "popup"
command = "lazygit"
description = "run lazygit"
width = "80%"
height = "80%"
```

`type = "popup"` opens a session-modal popup without changing the tab layout.
The popup receives all terminal input, including Escape, until its command
exits. `width` and `height` are optional; omit them for the default half-size
popup, use numbers for terminal cells, or use strings like `"80%"` for a
percentage of the terminal area. Dimensions include the popup border, and
values smaller than the popup minimum are clamped. Popup commands do not receive
`HERDR_PANE_ID`; use `HERDR_ACTIVE_PANE_ID` for the underlying tiled pane.

On Unix and macOS, a popup command can also provide an ad-hoc terminal without
adding a split or tab:

```toml
[[keys.command]]
key = "prefix+t"
type = "popup"
command = "exec \"${SHELL:-sh}\""
description = "open scratch terminal"
width = "80%"
height = "80%"
```

On Windows, use a shell command such as `command = "powershell.exe -NoLogo"`
instead. Exit the shell to close the popup and restore the tiled terminal view.

`type = "pane"` opens a temporary zoomed pane and closes it when the command exits.

`type = "shell"` runs detached in the background.

`type = "plugin_action"` invokes an installed plugin action id. Use the
qualified id when action ids are not globally unique:

```toml
[[keys.command]]
key = "prefix+l"
type = "plugin_action"
command = "example.layout.apply"
description = "apply layout"
```

An optional `description` can be provided. When specified, this description is displayed in the keybind help panel (opened with `prefix+?`) in place of the default `'custom command'` label.

Custom commands receive `HERDR_SOCKET_PATH`, `HERDR_BIN_PATH`, `HERDR_ACTIVE_WORKSPACE_ID`, `HERDR_ACTIVE_TAB_ID`, `HERDR_ACTIVE_PANE_ID`, and `HERDR_ACTIVE_PANE_CWD` when those values are available. Shell commands run from the focused pane's working directory when Herdr can detect it.

On Windows, custom command strings use `cmd.exe /d /c`, so environment variables use `%HERDR_BIN_PATH%` syntax. To run PowerShell syntax, invoke it explicitly, for example `powershell.exe -NoProfile -Command "..."`.

## Theme

Choose a built-in theme:

```toml
[theme]
name = "catppuccin"
```

Search `theme.name` in the [Config reference](/docs/config-reference/) for every built-in theme. Use `terminal` when you want Herdr UI colors to follow your host terminal's ANSI palette.

To let Herdr switch its own UI theme when the host terminal reports a light/dark appearance change, enable theme auto-switching:

```toml
[theme]
name = "catppuccin"
auto_switch = true
light_name = "catppuccin-latte"
dark_name = "catppuccin"
```

`auto_switch` defaults to `false`, so existing theme configs keep manual behavior. If `light_name` or `dark_name` is omitted, Herdr uses the matching built-in sibling for the configured `name` when one exists, such as `tokyo-night`/`tokyo-night-day` or `gruvbox`/`gruvbox-light`. Manual theme selection in Settings disables `auto_switch`.

You can override individual colors:

```toml
[theme.custom]
sidebar_bg = "#181825"
panel_bg = "reset"
accent = "#a6e3a1"
green = "#a6e3a1"
blue = "#89b4fa"
red = "#f38ba8"
yellow = "#f9e2af"
```

`sidebar_bg` optionally gives the desktop sidebar its own background. When omitted, the sidebar keeps the host terminal background.

Color values accept hex, named colors, `rgb(r,g,b)`, or reset aliases like `reset`, `default`, `none`, and `transparent`.

## UI and sidebar

The sidebar is the main Herdr dashboard. Search `ui.` in the [Config reference](/docs/config-reference/) for sizing, collapsed mode, Agent panel ordering, mouse behavior, pane borders, and other presentation settings.

Set `tab_bar_position = "bottom"` under `[ui]` to place the desktop tab row below the terminal panes. Prefix, Navigate, Copy, and Resize mode bars temporarily replace the bottom tab row while active. The default is `"top"`.

Agent status uses single-cell ascii marks by default — `!` blocked, `>` working, `-` idle, blank unknown — so every terminal draws them at the same width. Two alternatives are available: **color dots**, the compact colored marks, and **distinct symbols**, which separates blocked, working, done, idle, and unknown by shape as well as color. Choose one in Settings or configure:

```toml
[ui]
# "ascii" (default), "dots", or "symbols"
status_indicators = "symbols"
```

All three alphabets are static, so none of these options enables spinner animation.

### Sidebar row layouts

The expanded desktop sidebar renders each inner array in `rows` as one line. These are the complete default layouts:

```toml
[ui.sidebar.agents]
row_gap = 0
rows = [
  ["state_icon", "workspace", "tab"],
  ["agent"],
]

[ui.sidebar.spaces]
row_gap = 0
rows = [
  ["state_icon", "workspace"],
  ["branch", "git_status"],
]
```

Agent rows accept these built-in tokens:

- `state_icon` — colored icon for the agent's semantic state.
- `state_text` — `idle`, `working`, `blocked`, `done`, or `unknown`, including a reported display label when present.
- `state_age` — how long the agent has held that state, as a single unit: `9s`, `47m`, `3h`, `6d`.
- `workspace` — workspace name.
- `tab` — tab name when available.
- `pane` — pane name when available.
- `agent` — detected or reported agent display name.
- `terminal_title` — latest OSC 0/2 terminal title after safety normalization.
- `terminal_title_stripped` — the terminal title with one recognized leading activity or spinner glyph and its following whitespace removed.
- `$name` — custom pane metadata named `name`.

Space rows accept these built-in tokens:

- `state_icon` — colored icon for the space's rolled-up agent state.
- `state_text` — text for the rolled-up agent state.
- `state_age` — how long the rolled-up state has been held, from the same pane the icon describes.
- `workspace` — workspace name.
- `branch` — Git branch when available.
- `git_status` — Git ahead and behind counts when nonzero.
- `git_dirty` — uncommitted work in the checkout: `+` staged, `~` unstaged, `?` untracked.
- `pull_requests` — open pull requests on the repository this checkout pushes to, as `pr3`.
- `terminal_title` — latest OSC 0/2 terminal title after safety normalization, rolled up from one pane.
- `terminal_title_stripped` — the same rolled-up title with one recognized leading activity or spinner glyph and its following whitespace removed.
- `$name` — custom workspace metadata named `name`.

`git_dirty` and `pull_requests` both count outstanding work, so both stay silent
when there is none: a clean checkout draws no `git_dirty`, and a repository with
nothing open draws no `pull_requests`. Neither ever truncates. A shortened count
is a wrong count, so like `git_status` they keep their full width and let a long
branch name on the same row give way instead.

Both are acquired only for rows that ask for them, so a layout naming neither
costs nothing. `git_dirty` rides the existing Git refresh but rescans a checkout
at most once every five seconds, because its cost scales with the size of the
checkout rather than with a handful of ref files.

`pull_requests` crosses the network and refreshes every two minutes. It reads the
repository named by the remote the current branch tracks — falling back to
`origin` only when the branch tracks nothing — so a fork's checkout counts the
fork's pull requests rather than the upstream project's.

Only `github.com` is queried. The request carries a bearer token, and a remote's
hostname is no evidence that the host behind it speaks GitHub's API, so a
checkout pointing anywhere else draws no counter rather than being probed for
one. Herdr finds a token the way `gh` does, checking `HERDR_FORGE_TOKEN`,
`GH_TOKEN`, and `GITHUB_TOKEN`, then `gh`'s own configuration; with no token it
draws nothing and asks for none. When a fetch fails the previous count stays on
the row, because "we could not ask" is not "there is nothing open".

`state_age` reports elapsed time and nothing else. It is not a stall warning:
nothing about it changes colour or shape as the number grows, because Herdr has
no evidence that a long-held state is a bad one. Reading it that way is the
reader's call.

The unit coarsens as the state ages, so a state held for ninety minutes reads
`1h` rather than `90m`. That keeps the token to a few columns on a narrow
sidebar; when an exact figure matters, `herdr agent list` reports
`state_age_ms` in milliseconds.

The token renders nothing when Herdr does not know when the state changed —
before the first observed transition, and after a server restart, which does not
carry the timestamp. Like every other missing value it disappears together with
its separator, and takes the whole row with it if nothing else on that row has a
value. A live handoff does carry it, so replacing the server in place leaves the
elapsed times counting from where they were.

Rows that use `state_age` make Herdr repaint the sidebar when a drawn number
would change — about once a second while a state is seconds old, once a minute
once it is minutes old, and once an hour beyond that. Rows that do not use it
cost nothing.

A space can hold several panes, so its terminal title is rolled up from the same
pane that `state_icon` and `state_text` describe: the pane with the highest
attention priority (blocked, then finished-unseen, then working, then idle, then
unknown), resolving ties to the first pane in tab and layout order. An icon and a
title on one Space row therefore always describe one pane. A space with no panes,
no running terminals, or a winning pane that never set a terminal title renders no
title at all; like every other missing value it disappears together with its
separator, and its row disappears when nothing else on that row has a value. A
collapsed worktree group rolls its state icon up across member spaces, but each
row's title stays that space's own, matching `workspace` and `branch`.

Tokens render in their configured order. Herdr normally separates adjacent values with ` · ` and uses a single space after `state_icon`. Missing values and their separators disappear; a row disappears when none of its tokens have a value. Each layout may contain at most 16 rows, with at most 16 tokens in each row.

A token entry can also be an inline style table:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", { token = "workspace", bold = false }, "tab"],
  [{ token = "$summary", fg = "#89b4fa", bg = "#1e1e2e", bold = true, dim = false }],
  [{ token = "$note", italic = true, underline = true, reverse = false }],
]
```

`fg` and `bg` accept strict `#RGB` or `#RRGGBB`. `bold`, `dim`, `italic`, `underline`, and `reverse` accept booleans. Omitted fields preserve the token's contextual style; explicit `false` removes that modifier. Styling applies to one occurrence, so the same token may look different in another row or agent override. A foreground override replaces all semantic foregrounds inside that occurrence: for example, styled `git_status` ahead and behind counts use one color instead of their default green and red. A `bg` override paints only the cells that occurrence draws, so it reads as a token badge rather than a row background. Token styles never change separators or row backgrounds.

Terminal support for `italic`, `underline`, and `reverse` varies. Herdr emits the standard attributes and leaves the rest to your terminal.

`emphasis` names an animation behaviour for one occurrence. It is off by default:

```toml
[ui.sidebar.agents]
rows = [
  [{ token = "$dot", fg = "#a6e3a1", emphasis = "pulse" }],
]
```

Steady behaviours, which loop for as long as the row is on screen:

- `none` — the default. Renders exactly like a token without `emphasis`.
- `pulse` — breathes the token's foreground toward the panel background and back over about 1.6 seconds.
- `shimmer` — a bright band travels across the token, tinted toward the accent color.
- `wave` — a ripple along the token, each cell a little behind the one before it.
- `activity` — brightness *and* tempo follow how hard that row's busiest pane is working right now. A quiet row keeps a calm trace of its own color; a pane producing heavy output reads bright and fast.
- `activity-shimmer` — a travelling band whose speed follows the same work-volume signal.

Arrival behaviours, which run once and settle. Set as `emphasis` they loop instead, which is usually not what you want — see `[ui.sidebar.animation]` below for where they belong:

- `fade`, `typewriter`, `wipe`, `drop-in`, `dissolve`, `collapse`.

Every behaviour is drawn as a per-cell color ramp, not with terminal blink, so it stays legible throughout and works on terminals that ignore blink. Behaviours that tint ramp toward the occurrence's own `bg` when one is set, otherwise toward the panel background, so a tint on a token with no foreground color has nothing to ramp and stays static.

`activity` and `activity-shimmer` read the same per-pane work-volume level the socket API publishes as `pane.activity.level_percent`. It is sampled and smoothed inside Herdr on its own clock — nothing external has to publish it, and a pane that goes quiet settles back to rest on its own.

### Row arrivals and departures

A whole sidebar row can animate as it appears and as it leaves:

```toml
[ui.sidebar.animation]
row_enter = "wipe"
row_enter_ms = 320
row_exit = "wipe"
row_exit_ms = 220
```

`row_enter` takes any of the behaviour names above and defaults to `none`, which is how rows have always appeared: fully drawn on their first frame. `row_enter_ms` is clamped to 60–1500 ms. A row's arrival always wins over its tokens' own `emphasis`, so a token cannot start shimmering while the row under it is still arriving.

`row_exit` is the same list of names, played backwards — a row leaves the way it arrived, so you write one name twice rather than looking for a mirror-image behaviour. It defaults to `none`, which is how rows have always disappeared: gone on the very next frame. `row_exit_ms` is clamped to the same 60–1500 ms.

This is what makes an ownership tree read as live. Each worker and sub agent row belongs to the second mate it names in its `owner` token, and each row arrives and leaves on its own: spawning work under one second mate grows that group and only that group, and finishing it shrinks the group back once the departing row has played its exit. With `row_exit = "none"` the group still grows and shrinks — it just does it in one frame instead of moving.

A row that is still leaving is drawn but is no longer a target: its pane has already closed, so clicking it does nothing.

### Rows that move

`row_enter` and `row_exit` say what a row's *cells* do while it arrives and leaves. `row_motion` says whether the row also **moves**:

```toml
[ui.sidebar.animation]
row_motion = "slide"
```

With `slide`, an arriving row comes in from the panel's right edge while every row below it pans down to open its slot, and a departing row slides back out the way it came while they pan up to close it. It defaults to `none`, which is how rows have always behaved: they appear and disappear exactly where the layout puts them.

The tree's branch lines move with the rows. A card and the `├─` pointing at it stay attached throughout, and a row that is still crossing the panel draws no branch line yet — it appears with the card, at the moment the card lands. Where a row *is* does not change while it moves: clicking, scrolling and dragging during a transition all still land on the row the layout says they hit.

This is a separate setting rather than another `row_enter` name because position is not something a character cell can express — a glyph cannot leave its cell — so the two are orthogonal choices and either one alone is a whole answer. Turning motion on retires nothing: a row can dissolve *and* slide, dissolve without moving, or move without dissolving. Motion runs on the arrival and departure that `row_enter_ms` and `row_exit_ms` already time, so it needs no duration of its own, and asking for `row_motion` with `row_enter = "none"` still gives the row an arrival to move through.

Motion applies to the **pixel cards** only. It needs `[experimental] kitty_graphics` and `sidebar_card_shapes`, a host that reports its cell size, a panel at least 34 columns wide, and a proportional font on the machine — the same conditions the cards themselves need. Everywhere else the sidebar is characters, so there is nothing to move and rows appear and disappear on the frame the layout says they do, exactly as they always have. A `row_enter` effect still plays on those cells.

With `kitty_graphics` or `sidebar_card_shapes` off, or with no proportional font on the machine, `row_motion` changes nothing at all — not even how long a closed pane's row stays drawn. The remaining two conditions behave differently on purpose: the panel width and the host's cell size can both change while a row is already mid-flight, so they decide what is *drawn* rather than what a row's life is. Dragging the sidebar below 34 columns during a transition therefore stops the movement without cutting the row's arrival short.

### How smooth the movement is

Motion is quantised to **whole cell rows**, and it resolves at the panel's own 50 ms animation step. On a 9×18 px cell a row of vertical travel is about 72 px taken in four 18 px steps, so the movement reads as stepped rather than as a glide. `row_enter_ms` is effectively a frame count — 320 ms is about six frames — but past roughly 500 ms it is the cell grid, not the frame rate, that limits how many distinct positions a card can occupy.

Making it smooth needs two things this release does not have: sub-cell pixel placement, and a finer frame tier than the 50 ms step. Both are needed together — extra frames alone land on the same handful of cell rows. And once a card can sit at a fraction of a cell, the tree's branch lines cannot follow it, because a character occupies a whole cell row and there is no half-row position for `├─` or `│`. Smooth movement therefore also requires the trunk and branches to be drawn as pixel artwork rather than as characters. That is a known, measured boundary and the next piece of work, not an oversight — the measurements are in `data/herdr-row-slide-reflow/subcell-test/RESULT.md`.

### The fleet signal bar

Eight fixed slots on the row above the Spaces tree, saying what the fleet is waiting on:

```toml
[ui.sidebar.notifications]
enabled = true
emphasis = "pulse"
enter = "fade"
enter_ms = 220
```

The eight, in the order they always draw:

| Slot | Live when |
| --- | --- |
| `◉ask` | an agent is blocked waiting on your answer |
| `●review` | an agent finished while you were looking somewhere else |
| `≡report` | a worker has published a `summary` token that is still standing |
| `⊘stopped` | a pane a mate owns is no longer running an agent |
| `↑push` | some branch has commits its upstream does not have |
| `↓sync` | some upstream has commits the checkout does not have |
| `⋔pr` | a pull request wants you: a review requested of you, or one of yours sent back for changes |
| `✓checks` | a check run on a pull request you authored is failing or has not finished |

The first four are the fleet waiting on you; the last four are the repository
waiting on you. Every one of the eight has an owner, a definite act that clears
it, and somewhere to go — which is why "something is producing output right
now" is not among them. It has no owner, it clears itself, and it points at
every pane at once; it is carried instead as the notification tray's own tint.
Neither is "some checkout has uncommitted work", which is lit in every session
anyone is actually working in and is only the precondition for `push`.

Every slot is drawn in every frame. A quiet slot is its own name in the panel's muted grey; a live one takes its own colour, turns bold, and animates until the signal clears. The resting bar is the legend for the alerting bar, which is why it never hides a slot for being quiet. Two live slots may share a colour on themes that give two palette roles the same value, so a slot is identified by its mark and its fixed position — colour only tells you live from resting.

The bar gives up detail rather than slots as the panel narrows. The header row is one column narrower than the sidebar, so the three forms need a sidebar of:

- **53 columns** for the named form above — 45 columns of marks and names, plus a space between slots.
- **16 columns** for the marks alone, one space apart: `◉ ● ≡ ⊘ ↑ ↓ ⋔ ✓`.
- **9 columns** for the marks with no gaps: `◉●≡⊘↑↓⋔✓`.

Narrower than one column per signal it draws nothing rather than a prefix of itself: a bar showing five of eight marks gives you no way to know which five, which is worse than no bar. Note that `ui.sidebar_max_width` defaults to `36`, so the named form is out of reach until you raise it.

The bar hangs on the left of that row and any `herdr api status set` text right-aligns in whatever is left.

`enabled` defaults to `false`. Four of the slots read counts that cost a request to the forge or a read of a branch's upstream, and Herdr only pays for those while something is drawing them — so switching the bar on is also what arms those refreshes, exactly as configuring a `git_dirty` or `pull_requests` token does. `emphasis` takes any behaviour name above and defaults to `pulse`; set it to `none` for a bar that changes colour without moving. `enter`/`enter_ms` are the arrival a slot plays as it goes live, clamped to 60–1500 ms. A slot has no exit: it never leaves, it just goes back to grey.

Animation costs frames. Herdr keeps its animation clock stopped unless an expanded sidebar row actually asks for one, so a configuration without `emphasis` or `row_enter` repaints exactly as often as before. Each behaviour declares its own frame spacing: `pulse` repaints about 10 times a second, the behaviours with visible motion about 20, and a Herdr server never faster than 5 regardless. Collapsing the sidebar stops the clock, and a server with no client attached does not animate a sidebar nobody is looking at. Prefer one animated token over several.

### The notification tray

The same eight signals as a tray of badges at the foot of the Spaces panel — two
rows of four — where each one is something you can click and act on:

```toml
[ui.sidebar.signal_tray]
enabled = true
actions = true
```

A badge has three states. **Idle** is engraved into the panel: the slot is
empty right now, not broken. **Active** means the condition is true and
standing. **Attention** means it crossed from happening to finished and waiting
on you, and wears Herdr's alert hue plus a filled pip in its corner. `ask`,
`review` and `stopped` demand attention the moment they go live; `report`,
`sync`, `pr` and `checks` do so when the count behind them grows; `push` never
does, because commits do not get more urgent by sitting on the machine.

On a terminal with Kitty graphics the badges are drawn as images, each mark a
composition of a silhouette, an interior detail and a highlight. Everywhere
else the tray falls back to the one-cell marks from the table above, and works
the same way.

Clicking a badge opens a popover anchored above it, listing what that badge
covers by name; `···` at the right of the tray's header opens the same popover
holding the legend. What the popover offers depends on the badge:

| Badge | What a click can do |
| --- | --- |
| `ask` | **yes / no**, sent straight to the blocked pane, with the agent's actual question shown above the buttons |
| `review` | jump to the pane, or **mark all seen** |
| `report` | open the worker-summaries view |
| `stopped` | jump only |
| `push` | **push**, with the exact command, branch and count printed above the button |
| `sync` | **sync** (`git pull --rebase`), on the same terms — and **refused** on a tree that is not provably clean |
| `pr` | jump only |
| `checks` | jump only |

The four jumps are deliberate, not unfinished. Restarting a worker that died
needs a launch command Herdr does not record per pane, and "re-run the failed
jobs" is a decision rather than a yes.

Nothing in the tray forces, discards or overwrites work. `sync` is the only act
that could, so it refuses whenever the checkout has uncommitted changes — or
whenever Herdr has not read the tree at all, because "we do not know" has to
fail the same way "it is dirty" does. It then offers the jump instead, so you
can go and look.

`actions` defaults to `true`, and is the switch for whether a badge click may
run anything at all. With `actions = false` every badge becomes a jump: the same
eight slots light on the same eight conditions and the popover still names what
each covers, but no button will send keys to a pane or run git.

`enabled` defaults to `false`, for the same reason the signal bar does — and
then some. Switching the tray on arms the forge fetch and the branch-upstream
read that four of its slots need, *and* the `git status` scan that `sync`'s
refusal reads. That last one costs more the larger your checkout is, and the
signal bar deliberately does not arm it.

The tray takes ten rows off the bottom of the panel, or eight on a panel that
cannot spare ten. A panel too short to hold both the tray and a readable tree
keeps the tree and draws no tray.

### Re-rooting the tree on one mate

Double-click a row that owns a subtree and the Spaces tree re-roots onto it: that row takes rank 0, its own workers take rank 1, and everything else leaves the view. A `◂ main` control appears on the row above the tree to come back out, and double-clicking the row at rank 0 does the same.

Nothing slides. The view being left dematerializes where it is, the layout changes at the instant the panel is empty, and the view being arrived at materializes in place — so no row is ever animated from one position to another.

```toml
[ui.sidebar.animation]
view_switch = "dissolve"
view_switch_ms = 640
view_switch_particles_per_cell = 0
```

`view_switch` takes the same behaviour names as `row_enter`, and like `row_exit` the way out is that name played backwards — the view comes apart the way it formed. Unlike `row_enter` it is on by default, because re-rooting with no transition is a hard cut from one set of rows to another; `view_switch = "none"` restores that hard cut. `view_switch_ms` is how long *each half* takes, clamped to 60–1500 ms.

The transition redraws every 50 ms, so `view_switch_ms` is really a frame count rather than a continuous dial: 640 ms is about thirteen frames each way, and anything under about 250 ms is four frames or fewer — one intermediate state on the way in, one on the way out, and a lot of hard edge.

### Dissolving the pixel cards

`view_switch_particles_per_cell` is off (`0`) by default, and only does anything when [`experimental.kitty_graphics`](#experimental) is on.

With Kitty graphics on, the sidebar's cards are a picture drawn *over* the tree's characters and opaque across every cell a card occupies. The character dissolve is still running underneath it, but what you can actually see is a border of connectors coming apart around a block of cards standing perfectly still — and then jumping, all at once, at the commit instant. Setting this dissolves the cards themselves, in pixels.

The number is particles per terminal *cell*, so it means the same thing whatever size cell your terminal draws: `1` is the finest a character dissolve can be, matched exactly, and the count rises from there. It is clamped to 256, which is finer than a pixel on most cells.

Density is the cheap part. On a 41×37-cell panel holding ten cards, going from one particle per cell to twenty-one costs about a third more bytes per frame and about half a millisecond of CPU. What costs is switching it on at all: the card sheet goes from being re-encoded once per switch to once per frame — twenty-six times across a 640 ms switch, a few megabytes of PNG where today it is a couple of hundred kilobytes. That is fine on a local terminal and is worth thinking about over a slow link. `cargo test --release --bin herdr dissolve_cost -- --ignored --nocapture` re-measures all of it on your own machine.

The switch and the fleet run on separate clocks on purpose. A worker that spawns while the panel is coming apart still plays its own arrival, and a worker that finishes mid-switch still leaves — neither is queued behind the transition, and neither cancels it.

`row_gap` controls the blank terminal rows between entries, independently for the Agent and Space panels. It defaults to `0`, which packs entries together; set it to `1` to restore the previous spacing. It does not add spacing between the content lines declared in `rows`. Consecutive indented worktree children remain packed as one Space group.

Override the complete Agent layout for a known agent under `rows_by_agent`:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", "agent", "state_text"],
  ["workspace", "tab"],
]

[ui.sidebar.agents.rows_by_agent]
claude = [
  ["state_icon", "agent", "state_text"],
  ["terminal_title_stripped"],
  ["workspace", "tab"],
]
```

An override replaces `rows`; it does not extend it. Override keys are case-sensitive canonical agent IDs such as `claude`, `codex`, and `pi`. Detection aliases such as `claude-code` are not accepted. Agents without an override, including custom reported agents, use `rows`.

Custom `$name` tokens are dynamic values, not literal text. Add the token to a layout, then report its value from a script or plugin:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", "agent", "$model"],
  ["$summary"],
  ["workspace", "tab"],
]
```

```bash
herdr pane report-metadata <pane_id> \
  --source my-agent-hook \
  --token model=opus \
  --token summary="reviewing authentication"
```

Use `herdr workspace report-metadata` in the same way for custom Space tokens. Unreported custom tokens simply disappear.

Metadata reporters provide values only; styling stays in the local sidebar configuration. See [CLI reference: report metadata](/docs/cli-reference/#panes) for limits, clearing, sequencing, and expiry.

Sidebar row settings affect only the expanded desktop sidebar. Collapsed and mobile views keep their compact layouts.

### Agents panel view

`[ui.sidebar.agents.view]` declares which agents the Agents panel shows and in what order, using the same filter and sort grammar as the [`agent.view.set`](/docs/socket-api/#agent-view) socket command. Unlike `agent.view.set`, a declared view is read from `config.toml` at startup and on every config reload, so it survives a server restart without an external process reapplying it.

```toml
[ui.sidebar.agents.view]
label = "needs me"
filter = { op = "any", filters = [
  { op = "eq", field = "status", value = "blocked" },
  { op = "eq", field = "seen", value = false },
] }
sort = [{ field = "attention", order = "desc" }]
```

`filter` is a tree of `all`, `any`, `not`, `eq`, `in`, and `exists` operations over `status`, `workspace_id`, `tab_id`, `pane_id`, `agent`, `seen`, `state_change_seq`, and `{ token = "name" }` pane metadata. `sort` is an ordered list of `{ field, order }` tables over `workspace_order`, `tab_order`, `pane_order`, `attention`, `status`, `agent`, `seen`, `state_change_seq`, and `{ token = "name" }`. `order` is `"asc"` or `"desc"` and defaults to `"asc"`. A non-empty `sort` replaces `ui.agent_panel_sort` while the view is active. The same limits as the socket command apply: 8 nesting levels, 64 filter nodes, 32 values per `in`, and 8 sort keys.

Three sources can own the Agents view, and they rank `config` < `ui` < `plugin`:

- **`config`** — this key. A standing default the user wrote down once.
- **`ui`** — a view Herdr itself sets for the session. It temporarily overrides the standing default, because an in-the-moment gesture is more specific than a stored preference.
- **`plugin`** — a view set over `agent.view.set`. It wins outright: a plugin was installed and enabled on purpose, and a line of config must not silently disable it.

`agent.view.set` and `agent.view.clear` own only the plugin tier. `config` and `ui` are reserved source names and are rejected over the socket API, and clearing a plugin view reveals the config view again rather than jumping to an unfiltered panel.

The panel header always names the tier in charge, so a filter is never invisible:

```text
 agents      config:needs me · 3 hidden !
```

The count is how many agents the view is hiding, and the trailing `!` means one of them is blocked and waiting on you. Narrow sidebars drop the tier prefix and then the word `hidden`, but never the count. Clicking the header clears the tier that owns the view, revealing the next tier down; a config-declared view returns on the next config reload or restart.

An invalid view is never applied. Herdr ignores it, shows every agent, and reports what is wrong through the config diagnostic banner and `herdr config check`:

```text
invalid [ui.sidebar.agents.view]: unknown agent status `workin`; ignoring the declared view and showing every agent
```

## Notifications

Herdr can notify you when a background agent finishes or needs input:

```toml
[ui.toast]
delivery = "herdr"
delay_seconds = 1

[ui.toast.herdr]
position = "bottom-right"
```

Choose `herdr` for an in-app toast, `terminal` for an outer-terminal notification that works well over SSH, `system` for the local OS notification service, or `off` to disable popups. Herdr suppresses popups for the active tab. Search `ui.toast` in the [Config reference](/docs/config-reference/) for positions, delay behavior, and clipboard feedback settings.

On macOS, `system` tries `terminal-notifier` first and falls back to `/usr/bin/osascript` when it is unavailable or fails. The fallback appears as Script Editor in Notification Center and cannot activate the hosting terminal. Install `terminal-notifier` with `brew install terminal-notifier`. For a supported, detected terminal, it can activate the terminal app when you click the notification. Alternatively, choose `terminal` to let a supported outer terminal own the notification.

## Sound

Sound notifications play through the local Herdr client. Custom sounds must be mp3 files; relative paths are resolved from the config file's directory.

```toml
[ui.sound]
path = "sounds/notification.mp3"
done_path = "sounds/done.mp3"
request_path = "sounds/request.mp3"
```

`path` sets one sound for all sound notifications. `done_path` and `request_path` override only the finished and needs-input sounds.

Per-agent sound overrides accept `default`, `on`, or `off`. Use detected agent labels such as `claude`, `codex`, `devin`, or `droid` as keys. Droid is muted by default.

```toml
[ui.sound.agents]
droid = "off"
claude = "on"
```

## Kitty graphics

Kitty graphics rendering for attached local clients is experimental and disabled by default:

```toml
[experimental]
kitty_graphics = true
```

Enable it only when testing terminal image behavior.

With it on, the sidebar tree also draws its rows as rendered cards instead of as
box-drawing characters, on any panel at least 34 columns wide. The card is set in
a proportional face taken from the machine — Ubuntu Sans, DejaVu Sans, Liberation
Sans, Noto Sans and Free Sans on Linux, the system UI face on macOS, Segoe UI on
Windows. If none of those is installed the sidebar keeps its character cards.
Point it at a specific font with:

```toml
[experimental]
kitty_graphics = true
sidebar_card_font = "/usr/share/fonts/truetype/ubuntu/UbuntuSans[wdth,wght].ttf"
```

The path is read once at startup. Below 34 columns, with `kitty_graphics = false`,
or on a direct attach — where graphics are disabled anyway — the sidebar renders
its character cards exactly as before.

By default the tree is drawn as one image with each row's background painted into
it, so a card's glow stops at that image's rectangle rather than falling off into
what is behind it. Draw each card as its own transparent shape instead with:

```toml
[experimental]
kitty_graphics = true
sidebar_card_shapes = true
```

Each card then becomes its own image at its own placement — transparent everywhere
outside its own glow — so nothing has a rectangular edge to show, and two cards
that overlap have their glows blended by the terminal rather than one clipping the
other. The layout is unchanged: same rows, same tiers, same titles. The character
fallback is unchanged too, and applies to both.

## Agent session restore

Herdr resumes supported Agent conversations after a server restart by default:

```toml
[session]
resume_agents_on_restore = true
```

Only panes with a valid native session reference from an official integration can resume; other panes restore as normal shells. See [Session state and restore](/docs/session-state/) for supported Agents and persistence behavior.

## IME cursor tracking

On macOS, AI Agent TUIs that hide the hardware cursor can prevent native input-method candidate windows from following the focused pane. Reveal a cursor anchor for those panes with:

```toml
[experimental]
reveal_hidden_cursor_for_cjk_ime = true
cjk_ime_agents = ["claude", "pi", "codex"]
```

Restricting `cjk_ime_agents` avoids showing an extra hardware cursor in unrelated applications. Search these keys in the [Config reference](/docs/config-reference/) for accepted Agent names and cursor shapes.

## Prefix input source switching

On macOS and Windows, Herdr can temporarily switch to an ASCII-capable input source while prefix commands and prefix-launched modes are active:

```toml
[experimental]
switch_ascii_input_source_in_prefix = true
```

On macOS this switches to the current ASCII-capable keyboard layout; on Windows it switches the IME to English (ASCII) input. Herdr restores the previous input source when returning to terminal input or entering a text field. This setting has no effect on other platforms.

:::caution[Windows support is Korean IME only]
On Windows, support is currently limited to the Korean IME. With an IME for any other language, this setting leaves the input source unchanged.
:::
